# CrossApp

Наскрізний проєкт з практикуму крос-платформного програмування.

## Предметна область

- **Назва**: Склад
- **Сутності**: `Product` (товар), `StockBatch` (партія), `Warehouse` (склад), `Movement` (переміщення)
- **Призначення**: Облік залишків товарів за партіями та відстеження їх переміщення між складами.

## Структура solution

- `src/Core` — бібліотека класів (бізнес-логіка, доменні моделі, розбір даних, сховища та сервіси)
  - `Core/Abstractions/` — інтерфейси та контракти взаємодії (`ICatalogStore`)
  - `Core/Domain/` — сутності з поведінкою та захистом інваріантів (`Product`)
  - `Core/Dto/` — незмінні DTO-моделі для перенесення й зберігання даних (`ProductDto`, `ImportResult<T>`)
  - `Core/Storage/` — реалізації сховищ даних (`InMemoryCatalogStore`, `FileCatalogStore`)
  - `Core/Services/` — сервісний шар бізнес-операцій (`CatalogService`)
  - `Core/Import/` — розбір файлів CSV/JSON за допомогою pattern matching (`ProductCsvImporter`)
- `src/Cli` — консольний інтерфейс користувача (Composition Root, точка входу, демонстраційні сценарії)
- `data/` — тестові набори даних (`sample.csv`, `catalog.json`)

## Доменна модель та Сервісний шар

### Інваріанти сутності (`Product`)

1. **Обов'язковість рядкових полів** (`ArgumentException`): ідентифікатор `Id`, `Sku`, назва `Name` та одиниця виміру `Unit` не можуть бути `null`, порожніми або складатись лише з пробілів.
2. **Невід'ємний початковий залишок** (`ArgumentOutOfRangeException`): початкова кількість товару під час створення через фабрику `Create` не може бути меншою за 0.
3. **Коректність операцій приходу та видачі** (`ArgumentOutOfRangeException`): передана кількість товару для операцій `RegisterArrival` та `Issue` повинна бути строго більшою за нуль.
4. **Заборона перевитрати товару** (`InvalidOperationException`): операція `Issue` не дозволяє списати або видати товару більше, ніж є на поточному залишку (`amount <= _quantity`).

### Сервіси та Сховища (Lab 05)

- **Контракт сховища**: `ICatalogStore` ізолює доменну логіку та сервіси від конкретного способу збереження даних (`List`, `GetById`, `Add`, `Update`, `Remove`).
- **Реалізації сховища**:
  - `InMemoryCatalogStore` — збереження залишків у пам'яті (`Dictionary<string, Product>`), наповнюється тестовими даними з `SampleData`.
  - `FileCatalogStore` — файлове JSON-сховище (`data/catalog.json`) з кешуванням у пам'яті та автоматичним скиданням змін на диск (`Flush`).
- **Сервісний шар**: `CatalogService` реалізує прикладні сценарії (`Add`, `Receive`, `Issue`, `All`, `Find`, `Delete`), працюючи виключно через інтерфейс `ICatalogStore` (Dependency Inversion Principle).
